# Indoor Obstacle Dataset Collection & Benchmarking Guide (Windows)

**Project:** Blind Assistant — On-Device Obstacle Detection & Assistive Navigation  
**Target Environment:** Windows 10/11 with Python 3.10+  
**Target Architecture:** YOLOv11 Nano Mobile TFLite (`frontend/assets/models/yolo11n_float16.tflite`)

---

## 1. Safety Rules & Assistive Boundaries

> [!CAUTION]
> **CRITICAL SAFETY DIRECTIVE:**
> - The Blind Assistant app is an **experimental assistive tool**, NOT a certified mobility or life-safety system.
> - **NEVER** navigate unfamiliar or hazardous indoor spaces independently while relying on this application.
> - The app does **NOT** detect staircases, elevation drops, doors, glass surfaces, or wet floors.
> - Always maintain primary orientation aids (white cane, guide dog, or a sighted companion).

### Data Collection Safety Protocol:
1. **Always Be Accompanied or Stationary:** When recording video clips in indoor spaces, either:
   - Stand firmly in a fixed, safe location and slowly pan the camera across the scene, OR
   - Have a sighted partner walk with you and clear the path ahead.
2. **Never Look Down at Screens While Walking:** Do not look at phone preview screens while walking in hallways or rooms.
3. **Avoid Hazardous Environments:** Do not record near open stairwells, construction zones, wet floors, or transit platform edges.

## 2. Obstacle Taxonomy: Supported vs. Unsupported Classes

### A. Supported Classes in Current Baseline Model (COCO-80 Subset)
The current on-device model (`yolo11n_float16.tflite`) was trained on COCO-80. When evaluating the current baseline model or building a compatible dataset, annotate the following classes:

| Class Name | COCO ID | Navigation Significance | Examples / Where to Find |
| :--- | :---: | :--- | :--- |
| **`person`** | `0` | Dynamic collision hazard | Standing, walking, or seated people |
| **`chair`** | `56` | Low tripping / shin hazard | Dining chairs, desk chairs, armchairs, stools |
| **`couch`** | `57` | Large path blockage | Sofas, couches, benches, loveseats |
| **`bed`** | `59` | Low wide path blockage | Bed frames, mattresses, cots |
| **`dining table`** | `60` | Mid-height waist hazard | Dining tables, work desks, coffee tables |
| **`backpack`** | `24` | Floor tripping hazard | School bags, gym bags placed on floor/chairs |
| **`handbag`** | `26` | Floor/seat hazard | Purses, tote bags placed in walkways |
| **`suitcase`** | `28` | Heavy floor obstruction | Rolling luggage, carry-ons in corridors |
| **`potted plant`** | `58` | Floor obstacle | Plant pots, indoor planters |
| **`toilet`** | `61` | Restroom fixture obstacle | Bathroom bowls |
| **`tv`** | `62` | Fragile obstacle / console | Wall-mounted or stand TVs |
| **`laptop`** | `63` | Desk / table obstacle | Open or closed laptops on surfaces |
| **`refrigerator`** | `72` | Kitchen obstruction | Fridges |
| **`sink`** | `71` | Restroom/kitchen obstruction | Basins, kitchen sinks |
| **`dog` / `cat`** | `16` / `15` | Low moving obstacles | Pets in walking path |
| **`bottle` / `cup`** | `39` / `41` | Small obstacles on surfaces | Water bottles, mugs |

### B. Important Classes NOT Supported by Current Model

> [!WARNING]
> Do NOT expect the current baseline model to detect any of the following. If you annotate these classes, the current model will score 0% recall:
> - **`door`:** The baseline model CANNOT detect doors (closed, open, or revolving).
> - **`stairs`:** The baseline model CANNOT detect steps or staircases.
> - **`drop-off` / `curb`:** The model cannot perceive level changes.
> - **`wall` / `hallway` / `floor`:** Surface segmentation is not performed by this object detector.
> - **`trash can` / `wastebasket`:** Not part of the COCO-80 vocabulary.

            ├── train/
            ├── val/
            └── test/

## 4. Step-by-Step Beginner Workflow (Windows)

### Step 1: Record Short Video Clips Safely
1. Hold your smartphone at **chest height** (~1.2 to 1.4 meters above floor).
2. Tilt the phone **10° to 15° downward** so the floor ahead and mid-height obstacles are both visible in frame.
3. Record short **10 to 30 second videos** for each distinct space:
   - Example filename: `living_room_01.mp4`
   - Example filename: `kitchen_01.mp4`
   - Example filename: `hallway_01.mp4`
   - Example filename: `bedroom_01.mp4`
4. Copy the recorded video files from your phone into `data/raw_videos/`.

---

### Step 2: Extract Representative Frames Without Duplicates
Do not extract all 30 frames per second of video; consecutive frames are near-identical and will cause excessive labeling workload.

Run the automated frame extractor:
```powershell
python backend/extract_frames.py --input-dir data/raw_videos --output-dir data/extracted_frames --fps 1.0 --blur-threshold 35.0 --min-diff 0.04
```

**How it works:**
- `--fps 1.0`: Samples only 1 frame per second of footage.
- `--blur-threshold 35.0`: Automatically rejects blurry frames caused by rapid motion.
- `--min-diff 0.04`: Rejects redundant frames if the camera was stationary.
- Automatically preserves the video clip prefix in filenames (e.g., `living_room_01_f0001.jpg`).

---

### Step 3: Label Obstacles with Label Studio

#### 1. Install & Launch Label Studio on Windows
Open PowerShell and run:
```powershell
pip install label-studio
label-studio start
```
Label Studio will automatically open in your default browser at `http://localhost:8080`.

#### 2. Create a New Project
1. Click **Create Project**, enter a title (e.g. `Indoor Obstacles`).
2. Go to **Data Import** and drag all images from `data/extracted_frames/`.
3. Go to **Labeling Setup** -> **Custom template** -> **Code**, and paste the following XML configuration:

```xml
<View>
  <Image name="image" value="$image"/>
  <RectangleLabels name="label" toName="image">
    <Label value="person" background="#FF3838"/>
    <Label value="chair" background="#2C3E50"/>
    <Label value="couch" background="#E67E22"/>
    <Label value="bed" background="#9B59B6"/>
    <Label value="dining table" background="#1ABC9C"/>
    <Label value="backpack" background="#F1C40F"/>
    <Label value="suitcase" background="#34495E"/>
    <Label value="handbag" background="#E74C3C"/>
    <Label value="potted plant" background="#27AE60"/>
    <Label value="toilet" background="#3498DB"/>
    <Label value="tv" background="#95A5A6"/>
    <Label value="laptop" background="#D35400"/>
    <Label value="refrigerator" background="#16A085"/>
    <Label value="sink" background="#2980B9"/>
    <Label value="dog" background="#8E44AD"/>
    <Label value="cat" background="#F39C12"/>
    <Label value="bottle" background="#BDC3C7"/>
    <Label value="book" background="#7F8C8D"/>
  </RectangleLabels>
</View>
```

#### 3. Bounding Box Rules:
- Draw tight boxes around objects. Do not include excessive empty floor or background.
- If an obstacle is partially occluded (e.g., chair legs behind a table), label the visible portions.
- Empty images (containing only clear walking path / floor) are **valuable negative samples**! Leave them unlabeled so the model learns what an empty path looks like.

#### 4. Export Annotations
1. In Label Studio, click **Export** (top right).
2. Choose **YOLO** format.
3. Extract the downloaded ZIP file. Place the `.txt` label files into `data/labeled/labels/`.

---

### Step 4: Split by Video Clip (Prevent Data Leakage)

> [!IMPORTANT]
> **Why random splitting fails:** If 10 frames from `kitchen_01` are randomly scattered between `train` and `val`, the model memorizes the exact lighting and background, producing falsely inflated accuracy metrics. Splitting must be performed at the **video clip level**.

Run the clip-level dataset splitter:
```powershell
python backend/split_dataset.py --images-dir data/extracted_frames --labels-dir data/labeled/labels --output-dir data/indoor_obstacles --train-ratio 0.70 --val-ratio 0.20 --test-ratio 0.10
```

**Output:**
- `data/indoor_obstacles/images/train/`, `val/`, `test/`
- `data/indoor_obstacles/labels/train/`, `val/`, `test/`
- `data/indoor_obstacles/dataset.yaml`

---

### Step 5: Validate Dataset Integrity & Class Counts

Run the dataset validation script to verify coordinates, class bounds, and split integrity:
```powershell
python backend/validate_dataset.py --data data/indoor_obstacles/dataset.yaml
```

**Checks Performed:**
1. Verifies that all bounding box coordinates satisfy $0.0 \le cx, cy, w, h \le 1.0$.
2. Rejects degenerate boxes where width $\le 0$ or height $\le 0$.
3. Checks for orphaned images or missing labels.
4. Confirms that no video clip spans across multiple splits.
5. Displays a per-class count table highlighting high-priority navigation hazards.

---

### Step 6: Benchmark Baseline Model on Real Indoor Data

Once your validation split (`data/indoor_obstacles/images/val`) is prepared and verified, evaluate the current model:

```powershell
python backend/evaluate_detector.py --model frontend/assets/models/yolo11n_float16.tflite --dataset data/indoor_obstacles --split val --conf 0.35
```

The script computes:
- **Precision:** Percentage of reported obstacles that are real (low false alarms).
- **Recall:** Percentage of real obstacles that were successfully detected (safety critical).
- **False Negatives (Missed Obstacles):** Obstacles in the path that were missed.
- **Duplicate Detections:** Redundant overlapping boxes that would confuse speech guidance.
- **Latency (ms & FPS):** Preprocessing, inference, and postprocessing timings.
- Automatically saves results to `backend/evaluation_report.json`.
